# Погодный дайджест

Консольная утилита на Node.js. Принимает название города или список городов, получает прогноз погоды из открытого API (https://open-meteo.com/), выводит результат в читаемом виде в терминал и сохраняет отчёт в JSON-файл. При сбоях завершается с понятным сообщением и кодом 1.

Требования к окружению

- Node.js 20 или выше 
- npm 
- Доступ в интернет к `api.open-meteo.com` и `geocoding-api.open-meteo.com`.

Установка

```bash
git clone git@github.com:ksushapopova/weather_digest.git
cd weather_digest
npm install
cp .env.example .env
```

Отредактируйте `.env` при необходимости 

Переменные окружения

Все параметры читаются из `.env` через `dotenv` и имеют значения по умолчанию.
 `GEO_BASE_URL`  `https://geocoding-api.open-meteo.com/v1/search`  Базовый URL геокодинга 
`FORECAST_BASE_URL` `https://api.open-meteo.com/v1/forecast`  Базовый URL прогноза
`TIMEOUT_MS` `5000`                  Таймаут HTTP-запроса, мс
`REPORTS_DIR`  `reports`       Каталог для JSON-отчётов 
`UNITS`    `metric` Единицы измерения
`LANGUAGE`  `ru`     Язык названий из геокодера 

`.env` добавлен в `.gitignore` и не попадает в репозиторий. Шаблон — `.env.example`.

 Запуск

```bash
node src/index.js --city "Нижний Новгород" --days 3
```

Все параметры:

 `--city`  Обязателен Название города. Можно указать несколько через запятую: `--city "Москва, Санкт-Петербург"`. 
`--days`   не обязателен  Число дней прогноза, целое от 1 до 7. По умолчанию — 3. 
`--no-cache`  не обязателен    Игнорировать кэш и запросить данные заново. 
`-h`, `--help` не обязателен   Показать справку.
 Пример вывода

 ```
 Москва, Россия (55.75204, 37.61781)
┌────────────┬──────────┬──────────┬────────────┐
│ Дата       │ Мин °C   │ Макс °C  │ Осадки, мм │
├────────────┼──────────┼──────────┼────────────┤
│ 2026-09-12 │      9.6 │     17.0 │        0.0 │
│ 2026-09-13 │      9.1 │     16.3 │        0.0 │
│ 2026-09-14 │     10.4 │     19.3 │        0.0 │
└────────────┴──────────┴──────────┴────────────┘
```


При повторном запуске в тот же день данные берутся из кэша и город помечается `[кэш]`:

Москва, Россия (55.75204, 37.61781) [кэш]


Отчёты и кэш

- Отчёт сохраняется в `reports/{slug(city)}-{YYYY-MM-DD}.json`.
- `slug(city)` — транслит кириллицы в латиницу: `Москва` → `moskva`, `Нижний Новгород` → `nizhniy-novgorod`.
- Если файл за текущую дату существует, данные берутся из него без обращения к сети.
- Флаг `--no-cache` заставляет выполнить сетевой запрос заново.
- Каталог `reports/` добавлен в `.gitignore`.

Обрабатываемые ошибки

Не указан `--city`  `Обязательный параметр --city не указан` + справка, код 1 
`--city` пустой или из одних запятых `Параметр --city не может быть пустым` + справка код 1
`--days` не число  `Параметр --days должен быть целым числом` + справка код 1
`--days` вне 1..7 `Параметр --days должен быть в диапазоне 1..7` + справка код 1 
Неизвестный аргумент `Неизвестный аргумент: "..."` + справка код 1 
Город не найден  `Город не найден: "..."` код 1 или 0 (если хотя бы один город обработан) 
HTTP 4xx  `Некорректный запрос к API (HTTP 4xx)` код 1 или 0 
HTTP 5xx `Сервер API временно недоступен (HTTP 5xx)` код 1 или 0 
Нет сети `Не удалось выполнить запрос ...: <причина>` код 1 или 0 
Превышен таймаут `Превышен таймаут N мс: <url>` код 1 или 0 
Некорректный JSON в ответе `Ответ не является корректным JSON` код 1 или 0 

Коды завершения процесса:

- `0` — успех: хотя бы один город обработан; либо это справка `--help`.
- `1` — ошибка: аргументы некорректны, либо ни одного города обработать не удалось.

Тестирование API в Postman

Коллекция с двумя запросами (геокодинг и прогноз) и примерами ответов лежит в `docs/postman/`. Переменные коллекции: `baseUrl`, `city`, `lat`, `lon`.

Структура проекта

```
weather_digest/
├─ src/
│  ├─ api/             # клиент внешнего API
│  │  ├─ httpClient.js # fetch + AbortController + проверка статусов
│  │  ├─ geocoding.js  # поиск координат по названию города
│  │  └─ forecast.js   # прогноз по координатам
│  ├─ cli/
│  │  └─ parseArgs.js  # разбор --city, --days, --no-cache
│  ├─ errors/
│  │  └─ AppError.js   # классы ошибок приложения
│  ├─ services/
│  │  └─ weatherService.js  # «город → координаты → прогноз»
│  ├─ storage/
│  │  ├─ slugify.js         # транслит кириллицы
│  │  ├─ reportStorage.js   # сохранение/чтение отчётов
│  │  └─ cache.js           # кэш за текущую дату
│  ├─ format/
│  │  └─ consoleFormatter.js # таблица в терминал
│  ├─ config.js        # чтение переменных окружения
│  └─ index.js         # точка входа
├─ tests/              # тесты (node:test)
├─ docs/
│  └─ postman/         # экспортированная коллекция Postman
├─ .env.example
├─ .gitignore
├─ package.json
└─ README.md
```
Тесты

```bash
npm test
```

Покрывают: разбор аргументов, HTTP-клиент (успех, 4xx, 5xx, парсинг, таймаут, сетевой сбой), slugify, чтение/запись отчётов.

HTML-страница с отчётом (бонус)

В папке `public/` лежит простая HTML-страница, которая читает сохранённый JSON-отчёт
и отображает его средствами DOM API.

Запуск:

```bash
npm run serve
```
Можно:
- выбрать файл отчёта вручную (`<input type="file">`) — работает и без сервера;
- ввести имя файла из `reports/` и нажать «Загрузить» — работает через сервер.
